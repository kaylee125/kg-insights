# Knowledge Graph Insights 학습 볼트 — 설계

작성일: 2026-09-30 · 상태: 검토 대기

## 1. 목표

YouTube 채널 [Knowledge Graph Insights](https://www.youtube.com/@KnowledgeGraphInsights/videos)의 전체 에피소드 스크립트를 원본 그대로 로컬에 보존하고, 이를 AI로 2차 가공해 **채널이 다루는 인사이트를 학습하고 새 인사이트를 얻기 위한** 개인용 마크다운 볼트를 만든다.

용어 사전은 볼트의 일부일 뿐이다. 중심은 "누가 어떤 주장을 왜 했는가"와 "에피소드들을 가로질러 보면 무엇이 보이는가"이다.

### 성공 기준

1. 58개 에피소드 전부에 대해, 영상 처음부터 끝까지의 스크립트가 `raw/`에 있다.
2. 모든 에피소드 노트가 해당 영상의 전체 구간을 다룬다 (앞부분만 읽고 쓴 노트가 없다).
3. 볼트의 모든 인사이트·개념 설명에서 원문 위치(에피소드 + 타임스탬프 링크)로 되돌아갈 수 있다.
4. 주제 페이지만 읽어도 어떤 에피소드를 어떤 순서로 볼지 정할 수 있다.

### 범위 밖

- 재배포·공개 게시 (개인 학습용)
- 엔티티·관계 트리플 같은 구조화된 그래프 데이터 (필요해지면 볼트에서 변환)
- 게스트별 인물 페이지 (게스트 정보는 에피소드 노트의 frontmatter에 둔다)
- 새 에피소드 자동 동기화 (수집 스크립트를 다시 돌리면 이어받는 것으로 충분)

## 2. 확인된 사실 (2026-09-30)

- 채널 목록은 80개지만 같은 에피소드가 제목 구분자(`|` / `–`)만 다르게 두 번 올라온 것이 많다. 고유 에피소드는 58개, 합계 약 33.4시간이다. 에피소드 번호는 1~57이고 13번은 채널에 없다.
- 자막은 자동 생성본만 있다. 영어 원본은 `en-orig` 트랙이다. 화자 구분이 없고 전문 용어·인명 오인식이 있을 수 있다.
- 에피소드 57로 시험한 결과, 자막 마지막 시각 33:45 / 영상 길이 33:46으로 전체 구간이 들어 있었다. 5,924단어, 분당 176단어.
- 전체 분량은 약 35만 단어로 추정된다.
- `yt-dlp`는 설치돼 있지 않다. `uvx yt-dlp`로 설치 없이 실행된다.
- 팟캐스트 웹사이트 첫 화면에는 스크립트 언급이 없었다. 원본은 YouTube 자막으로 한다.

## 3. 폴더 구조

```
kg-insights/
  manifest.tsv          에피소드 번호, video_id, 길이, 제목, 게스트
  raw/                  원본. 받은 뒤 수정 금지
    ep057-TZZyOTmConw.en-orig.vtt
    ep057-TZZyOTmConw.info.json
  transcripts/          정제본. 타임스탬프가 붙은 문단
    ep057.md
  vault/                Obsidian으로 여는 폴더
    Index.md
    Episodes/           에피소드 노트 58개
    Concepts/           개념 페이지
    Themes/             에피소드를 가로지르는 주제 페이지
  scripts/
    fetch.sh            수집
    clean_vtt.py        정제
    check.py            완전성 검사 (아래 4절)
  docs/specs/           이 문서
```

`raw/`와 `transcripts/`는 볼트 밖에 둔다. 볼트 그래프에 스크립트 파일이 노드로 섞이지 않게 하기 위해서다.

## 4. 완전성 보장 — 30분 영상이면 30분 전체

스크립트가 중간에 잘리는 지점은 세 곳이다. 각 지점마다 검사를 두고, 통과하지 못한 에피소드는 다음 단계로 넘기지 않는다. 조용히 건너뛰는 일은 없다.

| 지점 | 잘릴 수 있는 이유 | 검사 (`check.py`) |
|---|---|---|
| 수집 | 다운로드 중단, 요청 제한, 자막 트랙 누락 | 마지막 자막 시각이 영상 길이와 60초(또는 길이의 3%) 이내 차이. 자막 사이 공백 120초 이하. 분당 100단어 이상 |
| 정제 | 중복 줄 제거 로직이 실제 발화를 지움 | 정제 전후 단어 수가 같음. 마지막 타임스탬프가 보존됨 |
| AI 추출 | 에이전트가 파일 앞부분만 읽음 | 에피소드 노트의 타임라인 구간이 00:00부터 영상 끝까지 빈틈없이 이어짐. 마지막 구간 끝이 영상 길이와 3분 이내 차이 |

임계값(60초, 120초, 분당 100단어, 3분)은 초기값이다. 인트로 음악 같은 정상적인 공백이 걸리면 파일럿에서 조정한다.

AI 추출에서 잘림을 막는 방법:

- 에피소드 하나에 에이전트 하나를 쓴다. 여러 편을 한 에이전트에 몰아주지 않는다.
- 정제본은 문단 단위라 한 편이 수백 줄 이하다. 한 번의 읽기로 전체가 들어온다.
- 노트에 타임라인 구간을 의무로 넣게 한다. 전체를 읽지 않으면 끝 구간을 쓸 수 없고, 검사에서 걸린다.

## 5. 처리 단계

1. **목록 확정** — 80개를 58개로 중복 제거해 `manifest.tsv`를 만든다. 쌍 중 하나를 고르고, 자막이 없으면 나머지 하나로 대체한다.
2. **원본 수집** — 에피소드마다 `en-orig` 자막(vtt)과 메타데이터(info.json)를 받는다. 요청 사이에 간격을 두고, 받은 목록을 기록해 중단 후 이어받는다. 수집 검사를 돌린다.
3. **정제** — 자동 자막의 반복 줄을 제거하고 약 30초 단위 문단으로 묶어 타임스탬프를 붙인다. 표준 라이브러리만 쓴다. 정제 검사를 돌린다.
4. **파일럿 추출** — 3편만 먼저 에피소드 노트를 만든다. 노트 형식과 검사 임계값을 함께 검토해 확정한다.
5. **전체 추출** — 확정된 형식으로 나머지 55편을 처리한다. 추출 검사를 돌린다.
6. **통합** — 에피소드 노트들에서 개념 페이지와 주제 페이지를 만든다. 주제는 미리 정하지 않고 58개 노트에서 실제로 반복되는 것에서 뽑는다.
7. **최종 검증** — 아래 8절.

AI 가공은 이 Claude Code 세션의 서브에이전트로 한다. 별도 API 스크립트는 만들지 않는다.

## 6. 볼트 노트 형식

언어는 한국어로 쓰고, 용어는 영어 원어를 병기한다. 모든 설명은 요약·재서술로 쓴다. 원문 인용은 한두 문장 이내로만 한다.

### 에피소드 노트 (`Episodes/EP57 Jessica Talisman - Ontology Pipeline.md`)

```
---
episode: 57
guest: Jessica Talisman
video_id: TZZyOTmConw
url: https://www.youtube.com/watch?v=TZZyOTmConw
duration: "33:46"
published: (info.json의 upload_date)
---
## 한 줄 요약
## 핵심 인사이트          3~7개. 각각: 주장 / 근거와 맥락 / 왜 중요한가 / [mm:ss](타임스탬프 링크)
## 타임라인               [00:00–05:10] 구간 요약 … 영상 끝까지. 완전성 검사 대상
## 다룬 개념              [[Ontology]], [[Taxonomy]] … 이 에피소드에서 어떻게 설명했는지 한 줄씩
## 적용 아이디어와 열린 질문   읽고 나서 생각해볼 것
## 인상적인 표현          짧은 인용 1~3개와 타임스탬프
```

### 개념 페이지 (`Concepts/Ontology.md`)

- 정의 (한국어 설명, 영어 원어, 별칭)
- 게스트별 관점: 누가 어떻게 설명했고 어디서 의견이 갈리는지, 에피소드 링크와 함께
- 관련 개념 `[[링크]]`

### 주제 페이지 (`Themes/LLM과 지식그래프.md` 같은 형태)

- 이 주제에서 여러 게스트가 공통으로 말하는 것
- 의견이 갈리는 지점
- 에피소드 순서에 따른 논의의 변화
- 추천 시청 순서

### 색인 (`Index.md`)

에피소드 목록, 주제 목록, 개념 목록.

## 7. 알려진 위험

- **자동 자막의 용어 오인식.** 게스트 이름은 영상 제목과 설명을 기준으로 한다. 전문 용어는 파일럿에서 교정 목록을 만들어 추출 지시에 넣는다. 확신이 없는 용어는 노트에 `(?)`로 표시한다.
- **YouTube 요청 제한.** 58편을 연속으로 받다 막힐 수 있다. 간격을 두고 받고, 실패한 편은 목록으로 남겨 나중에 다시 받는다.
- **화자 구분 없음.** 진행자와 게스트 발언이 섞여 있다. 인사이트의 주체가 불분명하면 "대화에서"로 쓰고 단정하지 않는다.

## 8. 최종 검증

- `check.py`가 58편 전부에 대해 세 검사를 통과한다.
- `vault/` 안의 모든 `[[링크]]`가 실제 파일을 가리킨다.
- 모든 개념 페이지와 주제 페이지에 에피소드 링크가 1개 이상 있다.
- 에피소드 5편을 뽑아 노트의 핵심 인사이트를 해당 타임스탬프의 정제본과 사람이 대조한다.
